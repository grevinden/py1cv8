Подсистема «Шифрование»

Руководство для разработчиков по использованию симметричного шифрования и управлению ключами.

Подсистема предоставляет возможность конфиденциальной обработки данных с использованием устойчивого симметричного шифрования. Ключ шифрования автоматически вычисляется на основе уникального идентификатора (УИД) объекта метаданных. Одна и та же операция выполняет и зашифрование, и расшифрование — повторный вызов с теми же параметрами восстанавливает исходные данные.

Детали алгоритма и механизм генерации ключа полностью скрыты внутри реализации. Публичный интерфейс оперирует только высокоуровневыми типами: ДвоичныеДанные, ХранилищеЗначения, УникальныйИдентификатор и адресами временного хранилища.

1. Состав модулей подсистемы

Подсистема включает два общих модуля с чётким разделением зон ответственности.

Модуль Флаги Назначение и публичные методы
ШифрованиеВызовСервераПовтИсп Сервер Вызов сервера Кэш сеанса Предоставляет интерфейс для клиентского кода. Данные передаются только через адрес временного хранилища. Кеширует результаты на время сеанса.
Методы:
  • ЕстьПравоНаШифрование()
  • ОбработатьАдресВременногоХранилища(Адрес, УИД)
ШифрованиеСервер Сервер Содержит базовую реализацию без кеширования. Доступен только в серверном коде. Может обрабатывать двоичные данные или извлекать их из ХранилищеЗначения.
Служебные методы:
  • ОбработатьДвоичныеДанные(Данные, УИД)
  • ОбработатьАдресВременногоХранилища(Адрес, УИД)

2. Публичные методы для клиентского кода

Все клиентские вызовы выполняются через модуль ШифрованиеВызовСервераПовтИсп. Прямая передача двоичных данных запрещена — необходимо использовать временное хранилище.

ОбработатьАдресВременногоХранилища(Адрес, УИД)

Выполняет шифрование или расшифрование данных, размещённых во временном хранилище. Результат также помещается во временное хранилище и возвращается его адрес.

Параметры

Имя Тип Описание
Адрес Строка Адрес временного хранилища, полученный через ПоместитьВоВременноеХранилище. Непустая строка, действительный адрес.
УИД УникальныйИдентификатор Уникальный идентификатор объекта, из которого будет сгенерирован ключ. Не может быть пустым.

Возвращаемое значение

Строка — адрес временного хранилища с результатом операции.

Исключения:
  • «Ожидается Строка» – неверный тип адреса.
  • «Ожидается не пустая Строка» – пустой адрес.
  • «Ожидается адрес временного хранилища» – строка не является адресом.
  • «Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)» – отсутствует роль.

Пример использования (клиент)

// Исходные данные
ДвоичныеДанные = ПолучитьДвоичныеДанныеИзСтроки("Важный текст", "UTF-8");
ИсходныйАдрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные);

// Уникальный идентификатор объекта
УИД = СсылкаНаОбъект.УникальныйИдентификатор();

// Шифрование
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
ЗашифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРезультата);

// Расшифровка (тот же вызов)
АдресРасшифровки = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(АдресРезультата, УИД);
РасшифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРасшифровки);

⚡ Кеширование: повторный вызов с теми же параметрами в рамках сеанса вернёт тот же адрес без повторной обработки.

ЕстьПравоНаШифрование()

Проверяет наличие у текущего пользователя роли ЧтениеКлючейШифрования, необходимой для выполнения операций шифрования.

Возвращаемое значение

Булево — Истина, если роль назначена.

Пример

Если ШифрованиеВызовСервераПовтИсп.ЕстьПравоНаШифрование() Тогда
    // вызов методов шифрования
КонецЕсли;

3. Методы для серверного кода

В серверном контексте вы можете напрямую обращаться к модулю ШифрованиеСервер, который выполняет операции без кеширования. При необходимости ускорения повторных вызовов используйте кеширующие обёртки из ШифрованиеВызовСервераПовтИсп.

ОбработатьДвоичныеДанные(Данные, УИД)

Шифрует или расшифровывает переданные двоичные данные. Параметр Данные может быть как объектом ДвоичныеДанные, так и ХранилищеЗначения — во втором случае данные будут автоматически извлечены через метод Получить().

Без кеширования (сервер): ШифрованиеСервер.ОбработатьДвоичныеДанные(...)

Параметры

Имя Тип Описание
Данные ДвоичныеДанные, ХранилищеЗначения Исходные данные. Если передан объект ХранилищеЗначения, из него автоматически извлекаются двоичные данные. Пустое значение не допускается.
УИД УникальныйИдентификатор Идентификатор объекта, формирующий ключ.

Возвращаемое значение

ДвоичныеДанные — результат операции.

Примеры

// Серверный код: работа с двоичными данными
Данные = ПолучитьДвоичныеДанныеИзСтроки("Секретные данные", "UTF-8");
УИД = СсылкаНаОбъект.УникальныйИдентификатор();
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Данные, УИД);

// Использование ХранилищеЗначения
Хранилище = Новый ХранилищеЗначения(Данные);
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Хранилище, УИД);

ОбработатьАдресВременногоХранилища(Адрес, УИД) на сервере

Выполняет те же действия, что и клиентский аналог, но может вызываться напрямую без дополнительного серверного вызова. Доступен через модуль ШифрованиеСервер (без кеширования).

АдресРезультата = ШифрованиеСервер.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);

4. Логика клиент-серверного взаимодействия и кеширования

  • → Клиент → Сервер: Модуль ШифрованиеВызовСервераПовтИсп имеет флаг «Вызов сервера», поэтому его методы прозрачно вызываются с клиента. Клиент передаёт только адрес временного хранилища и УИД, что полностью скрывает алгоритм шифрования.
  • ⏱ Кеширование «На время сеанса»: Модуль ШифрованиеВызовСервераПовтИсп повторно использует возвращаемые значения при идентичных параметрах. Это исключает повторные криптографические вычисления и снижает нагрузку на сервер. Кеш сбрасывается при завершении сеанса.
  • ✖ Модуль без кеширования (ШифрованиеСервер): Не использует кеш. Подходит для сценариев, где требуется гарантированное выполнение без хранения состояния (отладка, собственные кеширующие обёртки).
  • ● Гибкость входных данных: ШифрованиеСервер.ОбработатьДвоичныеДанные поддерживает как ДвоичныеДанные, так и ХранилищеЗначения, что упрощает интеграцию с типовыми механизмами, где данные часто упакованы в хранилище.

5. Рекомендации по использованию

  1. В клиентском коде всегда используйте ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища.
  2. Перед выполнением операций шифрования проверяйте права через ЕстьПравоНаШифрование().
  3. На сервере для однократных или некешируемых задач вызывайте ШифрованиеСервер. Для ускорения повторных операций с одинаковыми параметрами — кеширующие методы.
  4. Никогда не пытайтесь обращаться к методам модуля ШифрованиеСервер с клиента — они недоступны.
  5. Не сохраняйте сгенерированные ключи в открытом виде; все операции с ключами инкапсулированы внутри подсистемы.
  6. Для больших данных всегда применяйте временное хранилище — это справедливо и для серверного кода, если данные перемещаются между сеансами или контекстами.
