# Возможности приложения py1cv8

5 модулей:
- py1cv8_rawdatasource - чтение источника метаданных, это могут быть SQL или файлы:dt,xml,cf,cfe,1CD ; читает сырые данные и носителей конфигураций 1С
- py1cv8_parser - распаковывает сырые данные метаданных, возвращает сериализованные метаданные, `{...}`, скобочный формат 1С
- py1cv8_metadata - извлекают метаданные их скобочного формата 1С, превращая в полезные для работы объекты
- py1cv8_mcp - выполняет функции предоставления услу доступа к данным и металанных для агентов
- py1cv8 - общие утвердения , реэкспорт

## 1. Архитектура и базовые принципы
- **Прямой доступ к БД**: Чтение данных и метаданных напрямую из базы данных 1С (PostgreSQL,MsSQL) без использования сервера приложений 1С:Предприятие (без COM, OData, REST и т.д.).
- **Строгий Read-Only**: Все операции с базой данных выполняются в режиме "только чтение" (autocommit, разрешены только SELECT/WITH). Никаких INSERT/UPDATE/DELETE.
- **Мульти-базовость**: Поддержка одновременной работы с несколькими базами данных (`MultiDbProvider`), каждая со своими настройками подключения.
- **Чистая архитектура**: Использование паттерна Dependency Injection (DI) и контрактов (Contracts) для всех провайдеров (БД, метаданные, XML, DBNames, связи).
- **ORM**: Все взаимодействие с БД осуществляется через SQLAlchemy ORM (никаких "сырых" psycopg2-подключений).
- Извлечение полной структуры объектов: реквизиты (атрибуты), табличные части, формы, команды, значения перечислений.
- Извлечение бизнес-логики: иерархичность, подчиненность, типы номеров, периодичность, проведение, блокировка данных и т.д.
- Извлечение квалификаторов типов (длина строки, точность числа, формат даты).
- Приложение не имеет инструментов прикладной логики какойто конкретной базы, это ангностик конфигураций 1С , имеет инструменты которые применяются на любой базе 1С

## 2. MCP-сервер (Model Context Protocol)
- Реализация протокола MCP для интеграции с LLM (нейросетями), позволяющая ИИ "видеть" и понимать базу 1С.
- **Поддержка трех транспортов**:
  - `stdio` (стандартный ввод/вывод, для локальных процессов).
  - `sse` (Server-Sent Events, legacy HTTP-транспорт).
  - `http` (Streamable HTTP, рекомендуемый для удаленного доступа).
- **Ресурсы (Resources)**: Доступ к JSON-схемам таблиц по URI вида `e1c://{db}/tables/{table}`, `e1с://Справочники.Номенклатура`

## 3. Инструменты MCP (Tools) для LLM
### 3.1. Обзор и структура (Schema Discovery)
- `get_db_overview`: Полный обзор базы данных (типы объектов, количество, русские имена, соответствующие таблицы).
- `get_schema`: Детальная структура таблицы (колонки, типы данных, PRIMARY KEY, NULL-ability) или список всех таблиц базы.
- `search_metadata`: Поиск объектов 1С по UUID, категории (Справочники, Документы и т.д.) или имени (техническому или русскому).
- `analyze_object`: Детальный бизнес-анализ объекта (метаданные, связи, подтаблицы, XML-описание, бизнес-логика).
- `explain_object`: Комбинированный анализ объекта (метаданные + граф связей + примеры данных из таблицы).
- `get_relationship_map`: Полный граф связей таблицы (исходящие ссылки RRef/RTRef/Owner/Parent и входящие ссылки от других таблиц).

### 3.2. Выполнение запросов и работа с данными
- `run_sql`: Выполнение read-only SQL SELECT к базе 1С с автоматическим ограничением `LIMIT`.
  - **Разрешение имен (resolve_names)**: Автоматическая замена 1С-имен объектов (tech_name, display_ru) на физические имена таблиц в SQL-запросе.
- `table_stats`: Статистика таблицы (количество строк, процент NULL-ов, distinct-значения, диапазоны дат, топ-10 значений).
- `find_by_value`: Глобальный поиск значения (GUID, номер, имя) по всем строковым колонкам всех таблиц базы.
- `orphaned_records`: Поиск "битых" ссылок — записей, чьи поля RRef/RTRef указывают на несуществующие ID в целевых таблицах.

### 3.3. Работа с исходным кодом (BSL)
- `get_bsl_code`: Извлечение исходного кода модуля 1С (BSL) напрямую из ConfigStorage базы данных (без необходимости файловой выгрузки).
- `search_bsl_code`: Полнотекстовый поиск фрагмента кода во всех BSL-модулях конфигурации.
- `search_1c_queries`: Поиск 1С-запросов в BSL-коде с автоматическим переводом найденных запросов в SQL.

### 3.4. Управление конфигурацией и версиями (Diff & History)
- `get_config_snapshot`: Получение снимка конфигурации из `configsave.versions` (ожидающие изменения, которые еще не применены).
- `find_changed_objects`: Сравнение `configsave` (pending) и `config` (live) для поиска измененных, новых или удаленных объектов метаданных.
- `get_object_config_history`: История версий (configVersion) конкретного объекта метаданных.
- `config_diff_detail`: Детальный текстовый diff (унифицированный) содержимого объекта метаданных между configsave и config.

### 3.5. Специализированная аналитика
- **ЗАПРЕЩЕНО**: Приложение не должно содержать инструментов прикладной логики конкретной базы данных.
- Все MCP-tools должны быть агностичными и работать с любой конфигурацией 1С.
- Специализированные отчёты (например, аналитика уведомлений, продажи, складской учёт) создаются пользователем через `run_sql` + `get_schema`.

## 4. Парсинг и понимание метаданных 1С
### 4.1. Извлечение из бинарных блобов (БД)
- **DBNames**: Чтение и распаковка (zlib) бинарного блоба из таблицы `params`. Парсинг записей вида `{UUID,"Reference",53}` для построения соответствия "1С-тип → таблица БД".
- **Config/ConfigCas**: Чтение сжатых блобов из таблиц `config` и `configcas`. Извлечение UUID, type_num, технических имен и русских синонимов.
- **MOXCEL**: Парсинг заголовков блобов configcas для определения типа метаданных.

### 4.2. Извлечение из XML-выгрузки
- В справочный целях, для организации прямого доступа к метаданных, в каталоге `.staff/.export_from_1c/` находиться эталонная выгрузка конфигурации 1С
- Парсинг XML-файлов выгрузки конфигурации 1С (формат ConfigDumpInfo, директория `.staff/.export_from_1c/`).
- В продуктивной среде у приложения не будет других источников данных кроме прямого доступа на чтение в SQL
- Все типы ConfigDumpInfo должны парситься напрямую из базы SQL.


### 4.3. Граф связей (Relationships)
- Автоматическое определение межтабличных ссылок на основе анализа имен колонок:
  - `_RRef`, `_RTRef` (прямые ссылки по номеру таблицы).
  - `_Owner`, `_Parent`, `_Recorder`, `_Folder` (типизированные ссылки).
  - `_fldXXXrref` (ссылки по номеру поля).
- Построение полного графа "кто на кого ссылается" (outgoing) и "кто ссылается на меня" (incoming).
- Агент должен понимать связи метаданных и возникающие в сязи с этим связи таблиц SQL.

## 5. Трансляция запросов 1С в SQL (Query Translator)
- Извлечение текстов запросов из BSL-кода (паттерн `Запрос.Текст = "..."`).
- Перевод языка запросов 1С в SQL (поддержка диалектов PostgreSQL и MSSQL) с использованием SQLAlchemy expression trees.
- Трансляция ключевых слов 1С (ВЫБРАТЬ, ИЗ, ГДЕ, СОЕДИНЕНИЕ, ПО, УПОРЯДОЧИТЬ ПО и т.д.).
- Обработка виртуальных таблиц (СрезПоследних, Остатки, Обороты, ДвиженияССубконто и т.д.).
- Трансляция функций работы с датами (Год, НачалоПериода, ДобавитьКДате, РазностьДат, ДатаВремя).
- Разрешение имен таблиц (Справочник.Контрагенты → `_referenceXX`).
- Обработка параметров запросов (`&Параметр` → `:Параметр`).

## 6. Извлечение и декодирование (устарело, нужна декомпозиция)
- Должно быть выделено в отдельный модуль `py1cv8_parser` с обособленной системой тестирования.
- Должно предоставлять суперфункции для парсинга упакованных данных, простая работа, mcp дал адрес базы, парсер распаковал, вернул словарь, mcp интерпритирует далее самостоятельно
- Декомпрессия блобов (zlib с разными размерами окон: -15, +15).
- Автоматическое определение кодировки (chardet + fallback на cp1251, koi8-r, utf-16 и т.д.).
- Разделение блобов на модули по BOM-маркерам (UTF-8, UTF-16).
- Очистка кода от служебных заголовков, удаление дублирующихся пустых строк и форматирование.

## 7. Сравнение баз данных (Multi-DB Comparison)
- Сравнение схем таблиц между несколькими базами данных (наличие таблиц, колонки, типы данных).
- Сравнение количества строк в таблицах.
- Поиск различий в колонках (отсутствующие колонки, измененные типы данных).
- Сравнение высокоуровневых сводок (количество таблиц, примерное общее количество строк через pg_stat_user_tables).

## 8. CLI (Интерфейс командной строки)
- `py1cv8 mcp`: Запуск MCP-сервера (stdio по умолчанию).
- `py1cv8 schema --db-url <url>`: Вывод сводки по схеме базы данных (количество объектов, таблицы, категории).
- Поддержка переменных окружения (`PY1CV8_DB_URL`).

## 9. Вспомогательные возможности
- **Логирование**: Запись нераспознанных типов метаданных (type_num, DBNames types) в лог-файл для последующего расширения маппинга.
- **Кэширование**: Lazy Singleton `SchemaLoader` кэширует загруженные схемы реестров для каждой базы данных.
- **Инкрементальное обновление**: Поддержка `stale_uuids` — сравнение configVersion для инвалидации кэша при изменении объектов.
- **Строгая типизация**: Использование Pydantic для валидации конфигов и SQLAlchemy 2.0 Mapped аннотаций для ORM-моделей.
- **ORM-модели системных таблиц**: Описаны модели для `config`, `configcas`, `params`, а также представлений `information_schema` (columns, table_constraints, key_column_usage).
